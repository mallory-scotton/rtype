## Prerequisites

### Hardware Requirements

**Minimum Requirements:**
- **CPU**: Dual-core processor @ 2.0 GHz
- **RAM**: 4 GB
- **Storage**: 2 GB available space
- **Graphics**: OpenGL 3.3 compatible GPU

**Recommended Requirements:**
- **CPU**: Quad-core processor @ 3.0 GHz or higher
- **RAM**: 8 GB or more
- **Storage**: 5 GB available space (including build artifacts)
- **Graphics**: Dedicated GPU with OpenGL 4.5+ support
- **Network**: Stable internet connection for multiplayer testing

### Software Requirements

#### Operating System Support

The project supports the following platforms:

| Platform | Versions | Architecture |
|----------|----------|--------------|
| **Linux** | Ubuntu 20.04+, Debian 11+, Fedora 35+, Arch Linux | x86_64 |
| **Windows** | Windows 10/11 | x64 |
| **macOS** | macOS 10.15+ (Catalina or later) | x86_64, ARM64 (M1/M2) |

#### Required Tools

Before beginning, ensure you have the following tools installed:

1. **CMake** (version 3.21 or higher)
   - Build system generator and configuration tool
   - Download from: https://cmake.org/download/

2. **Python** (version 3.7 or higher)
   - Required for Conan package manager
   - Must include `pip` (Python package installer)
   - Download from: https://python.org

3. **C++ Compiler** with full C++20 support:
   - **Linux**: GCC 10+ or Clang 12+
   - **Windows**: Visual Studio 2019+ (MSVC v142+) or MinGW-w64
   - **macOS**: Xcode 12+ or Apple Clang 12+

4. **Git** (version 2.0 or higher)
   - Version control system
   - Required for cloning the repository

#### Optional Tools

- **Clang-Format 19**: Code formatting (recommended for contributors)
- **Ninja**: Alternative build system (faster than Make)
- **ccache**: Compiler cache for faster rebuilds
- **VS Code** or **CLion**: Recommended IDEs with C++ support

## Installation Methods

### Quick Start (Automated)

The **automated build scripts** handle all dependency installation, configuration, and compilation. This is the **recommended method** for first-time users and quick setup.

#### Linux / macOS / BSD

```bash
# 1. Clone the repository
git clone https://github.com/mallory-scotton/rtype.git
cd rtype

# 2. Make the build script executable
chmod +x Scripts/Build.sh

# 3. Run the automated build
./Scripts/Build.sh
```

#### Windows

```cmd
REM 1. Clone the repository
git clone https://github.com/mallory-scotton/rtype.git
cd rtype

REM 2. Run the automated build
Scripts\Build.bat
```

#### What the Automated Scripts Do

The build scripts automatically perform the following operations:

1. ✅ Detect your operating system and package manager
2. ✅ Install system-level dependencies (build tools, Python packages)
3. ✅ Install and configure Conan package manager
4. ✅ Create and configure Conan profiles
5. ✅ Download and build all project dependencies
6. ✅ Configure CMake with appropriate settings
7. ✅ Compile the entire project (Engine, Tools, Games)
8. ✅ Set up pre-commit hooks for development

#### Build Script Options

The Linux/macOS build script supports several command-line options:

```bash
./Scripts/Build.sh [options]

Options:
  --installer=<name>              Specify package manager (apt, yum, dnf, pacman, brew, zypper)
  --skip-package-installation     Skip system package installation
  --skip-conan-installation       Skip Conan dependency installation
  --clean                         Clean existing build directory before building
  --help                          Display help information
```

**Example Usage:**

```bash
# Clean build from scratch
./Scripts/Build.sh --clean

# Skip system packages (if already installed)
./Scripts/Build.sh --skip-package-installation

# Specify package manager explicitly
./Scripts/Build.sh --installer=dnf
```

### Manual Installation

For users who prefer manual control over the build process or need customization, follow these detailed steps.

#### Step 1: Install System Dependencies

**Linux (Ubuntu/Debian):**
```bash
sudo apt update
sudo apt install -y build-essential cmake python3 python3-pip pipx git
sudo apt install -y libgl1-mesa-dev libglu1-mesa-dev libx11-dev libxrandr-dev
```

**Linux (Fedora/CentOS/RHEL):**
```bash
sudo dnf groupinstall "Development Tools"
sudo dnf install cmake python3 python3-pip git
sudo dnf install mesa-libGL-devel mesa-libGLU-devel libX11-devel libXrandr-devel
```

**Linux (Arch):**
```bash
sudo pacman -Syu
sudo pacman -S base-devel cmake python python-pip git
sudo pacman -S mesa glu libx11 libxrandr
```

**macOS:**
```bash
# Install Homebrew (if not present)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install dependencies
brew install cmake pipx git
brew install python@3.11
```

**Windows:**
1. Install [Visual Studio 2019+](https://visualstudio.microsoft.com/downloads/)
   - Select "Desktop development with C++"
   - Include CMake tools component
2. Install [Python 3.x](https://www.python.org/downloads/windows/)
   - Check "Add Python to PATH" during installation
3. Install [Git for Windows](https://git-scm.com/download/win)

#### Step 2: Install Conan Package Manager

Conan manages all C++ dependencies for the project.

**Linux/macOS:**
```bash
# Install pipx (if not already installed)
pipx ensurepath

# Install Conan via pipx
pipx install conan

# Verify installation
conan --version
```

**Windows (PowerShell):**
```powershell
# Install Conan via pip
python -m pip install --user conan

# Verify installation
conan --version
```

#### Step 3: Configure Conan Profile

Create a default Conan profile matching your system:

```bash
# Generate default profile
conan profile detect --force

# Optional: View your profile
conan profile show default
```

For **advanced users**, you can customize your profile:

```bash
# Edit the profile
conan profile path default
# Then edit the file to adjust compiler, C++ standard, etc.
```

#### Step 4: Clone the Repository

```bash
# Clone via HTTPS
git clone https://github.com/mallory-scotton/rtype.git

# Or via SSH (if configured)
git clone git@github.com:mallory-scotton/rtype.git

# Navigate to project directory
cd rtype
```

#### Step 5: Install Project Dependencies

Install all C++ dependencies using Conan:

```bash
# Create build directory
mkdir -p Build

# Install dependencies
conan install . \
  --output-folder=Build \
  --build=missing \
  --settings=build_type=Release \
  --settings=compiler.cppstd=20 \
  -c tools.system.package_manager:mode=install
```

**Note:** The first run may take 10-30 minutes as Conan builds dependencies from source.

#### Step 6: Configure CMake

Configure the project using CMake:

```bash
cmake -B Build -S . \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
```

**Optional CMake Configuration:**

```bash
# Debug build
cmake -B Build -S . -DCMAKE_BUILD_TYPE=Debug

# Use Ninja generator (faster)
cmake -B Build -S . -G Ninja -DCMAKE_BUILD_TYPE=Release

# Specify compiler explicitly
cmake -B Build -S . -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_BUILD_TYPE=Release
```

#### Step 7: Build the Project

Compile all components:

```bash
# Build with all available CPU cores
cmake --build Build --config Release --parallel

# Or specify number of jobs
cmake --build Build --config Release -j 8
```

**Build specific targets:**

```bash
# Build only the R-Type game client
cmake --build Build --target RTypeGameClient

# Build only the server
cmake --build Build --target RTypeGameServer

# Build the engine tests
cmake --build Build --target TKDEngineTests
```

## Building the Project

### Build Configuration Options

The project supports multiple build types:

| Build Type | Description | Use Case |
|------------|-------------|----------|
| **Release** | Optimized build with no debug info | Production, performance testing |
| **Debug** | Full debug symbols, no optimizations | Development, debugging |
| **RelWithDebInfo** | Optimized with debug info | Profiling, release debugging |
| **MinSizeRel** | Optimized for binary size | Embedded systems, distribution |

**To change build type:**

```bash
# Configure for Debug
cmake -B Build -S . -DCMAKE_BUILD_TYPE=Debug

# Rebuild
cmake --build Build --config Debug --parallel
```

### Build Targets

The project includes the following build targets:

#### Game Executables
- **RTypeGameClient**: R-Type game client (with graphics)
- **RTypeGameServer**: R-Type dedicated server (headless)
- **BeatSaberGameClient**: Beat Saber VR game client
- **BeatSaberGameServer**: Beat Saber dedicated server

#### Engine Libraries
- **TKDEngineClient**: Game engine client library
- **TKDEngineServer**: Game engine server library

#### Development Tools
- **TKDPack**: Asset packing utility
- **TKDEmbed**: Resource embedding tool
- **TKDEngineTests**: Engine unit test suite

#### Utility Targets
- **format**: Format all source code with Clang-Format
- **all**: Build all targets (default)

### Build Output

After successful compilation, outputs are organized as follows:

```
Build/
├── bin/                    # Executable binaries
│   ├── RTypeGameClient
│   ├── RTypeGameServer
│   ├── BeatSaberGameClient
│   ├── BeatSaberGameServer
│   ├── TKDEngineTests
│   └── Assets/            # Game assets directory
│
└── libs/                   # Shared libraries
    ├── libTKDEngineClient.so
    ├── libTKDEngineServer.so
    ├── libRTypeGameClient.so
    └── libRTypeGameServer.so
```

## Running the Applications

### Running the R-Type Game

#### Starting the Server

The game server must be started before clients can connect:

```bash
# Navigate to build output directory
cd Build/bin

# Start the R-Type server
./RTypeGameServer

# Server will display:
# [INFO] R-Type Server starting on port 4242...
# [INFO] Server ready and listening for connections
```

**Server Configuration:**

The server can be configured via command-line arguments:

```bash
# Specify custom port
./RTypeGameServer --port 4242

# Set maximum players
./RTypeGameServer --max-players 8

# Enable verbose logging
./RTypeGameServer --verbose
```

#### Starting the Client

Once the server is running, launch one or more clients:

```bash
# In the same or different terminal
cd Build/bin

# Start the R-Type client
./RTypeGameClient

# The client GUI will appear with connection options
```

**Client Configuration:**

```bash
# Connect to specific server
./RTypeGameClient --host 192.168.1.100 --port 4242

# Fullscreen mode
./RTypeGameClient --fullscreen

# Windowed mode with specific resolution
./RTypeGameClient --width 1920 --height 1080
```

#### Multiplayer Testing

To test multiplayer locally:

```bash
# Terminal 1: Start server
cd Build/bin
./RTypeGameServer

# Terminal 2: Start first client
cd Build/bin
./RTypeGameClient

# Terminal 3: Start second client
cd Build/bin
./RTypeGameClient
```

Both clients should connect to `localhost:4242` automatically.

### Running the Beat Saber Game

**Prerequisites:**
- VR headset connected (HTC Vive, Oculus Rift, Valve Index, etc.)
- SteamVR or OpenVR runtime installed and running

```bash
cd Build/bin

# Start Beat Saber server
./BeatSaberGameServer

# In another terminal, start the VR client
./BeatSaberGameClient
```

### Running Engine Tests

Execute the test suite to verify your build:

```bash
cd Build/bin

# Run all tests
./TKDEngineTests

# Run specific test suite
./TKDEngineTests "[Network]"

# List all available tests
./TKDEngineTests --list-tests

# Verbose output
./TKDEngineTests --success
```

### Using Development Tools

#### TKDPack - Asset Packing Utility

Pack game assets into optimized archives:

```bash
cd Build/bin/Tools

# Pack a directory of assets
./TKDPack --input ../../Assets --output GameAssets.tkdpak

# Pack with compression
./TKDPack --input ../../Assets --output GameAssets.tkdpak --compress

# List contents of a pack file
./TKDPack --list GameAssets.tkdpak
```

#### TKDEmbed - Resource Embedding

Embed resources directly into executables:

```bash
cd Build/bin/Tools

# Embed a resource file
./TKDEmbed --input icon.png --output icon.h --name ICON_DATA

# Generate C++ header with embedded data
./TKDEmbed --input config.json --output config_data.h --namespace GameConfig
```

## Development Environment Setup

### Visual Studio Code Configuration

For the best development experience with VS Code:

#### 1. Install Required Extensions

Install these extensions from the VS Code marketplace:

- **C/C++** (ms-vscode.cpptools) - IntelliSense, debugging
- **CMake Tools** (ms-vscode.cmake-tools) - CMake integration
- **clangd** (llvm-vs-code-extensions.vscode-clangd) - Alternative language server
- **GitLens** (eamodio.gitlens) - Git integration
- **Todo Tree** (gruntfuggly.todo-tree) - TODO tracking

#### 2. Configure Workspace Settings

Create `.vscode/settings.json` in the project root:

```json
{
  "C_Cpp.default.configurationProvider": "ms-vscode.cmake-tools",
  "C_Cpp.default.compileCommands": "${workspaceFolder}/Build/compile_commands.json",
  "cmake.buildDirectory": "${workspaceFolder}/Build",
  "cmake.configureSettings": {
    "CMAKE_BUILD_TYPE": "Debug",
    "CMAKE_EXPORT_COMPILE_COMMANDS": "ON"
  },
  "files.associations": {
    "*.hpp": "cpp",
    "*.h": "cpp"
  },
  "editor.formatOnSave": true,
  "[cpp]": {
    "editor.defaultFormatter": "ms-vscode.cpptools"
  }
}
```

#### 3. Configure Tasks

Create `.vscode/tasks.json` for build tasks:

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "Build All",
      "type": "shell",
      "command": "cmake --build Build --config Debug --parallel",
      "group": {
        "kind": "build",
        "isDefault": true
      },
      "problemMatcher": ["$gcc"]
    },
    {
      "label": "Build RType Client",
      "type": "shell",
      "command": "cmake --build Build --target RTypeGameClient",
      "group": "build"
    },
    {
      "label": "Run Tests",
      "type": "shell",
      "command": "./Build/bin/TKDEngineTests",
      "group": "test"
    }
  ]
}
```

#### 4. Configure Debugging

Create `.vscode/launch.json` for debugging:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug RType Client",
      "type": "cppdbg",
      "request": "launch",
      "program": "${workspaceFolder}/Build/bin/RTypeGameClient",
      "args": [],
      "stopAtEntry": false,
      "cwd": "${workspaceFolder}/Build/bin",
      "environment": [],
      "externalConsole": false,
      "MIMode": "gdb",
      "setupCommands": [
        {
          "description": "Enable pretty-printing for gdb",
          "text": "-enable-pretty-printing",
          "ignoreFailures": true
        }
      ]
    },
    {
      "name": "Debug RType Server",
      "type": "cppdbg",
      "request": "launch",
      "program": "${workspaceFolder}/Build/bin/RTypeGameServer",
      "args": [],
      "stopAtEntry": false,
      "cwd": "${workspaceFolder}/Build/bin",
      "environment": [],
      "externalConsole": false,
      "MIMode": "gdb"
    }
  ]
}
```

### Code Formatting Setup

#### Install Clang-Format

**Linux (Ubuntu/Debian):**
```bash
wget -O - https://apt.llvm.org/llvm-snapshot.gpg.key | sudo apt-key add -
sudo add-apt-repository "deb http://apt.llvm.org/$(lsb_release -cs)/ llvm-toolchain-$(lsb_release -cs)-19 main"
sudo apt update
sudo apt install clang-format-19
```

**macOS:**
```bash
brew install clang-format
```

**Windows:**
Download from [LLVM releases](https://releases.llvm.org/download.html) or use Chocolatey:
```powershell
choco install llvm
```

#### Manual Formatting

```bash
# Format a single file
clang-format-19 -i path/to/file.cpp

# Format all C++ files in the project
find . -regex '.*\.\(cpp\|hpp\|h\|c\)' -exec clang-format-19 -i {} \;

# Or use the CMake target
cmake --build Build --target format
```

#### VS Code Auto-Format

Add to your `.vscode/settings.json`:

```json
{
  "C_Cpp.clang_format_path": "clang-format-19",
  "C_Cpp.clang_format_style": "file",
  "editor.formatOnSave": true
}
```

## Troubleshooting

### Common Build Issues

#### Issue: "CMake version too old"

**Problem:** CMake version is below 3.21

**Solution:**
```bash
# Linux: Install from Kitware repository
wget -O - https://apt.kitware.com/keys/kitware-archive-latest.asc | sudo apt-key add -
sudo apt-add-repository 'deb https://apt.kitware.com/ubuntu/ $(lsb_release -cs) main'
sudo apt update
sudo apt install cmake

# macOS: Upgrade via Homebrew
brew upgrade cmake

# Or download directly from cmake.org
```

#### Issue: "Conan profile not found"

**Problem:** Conan profile hasn't been created

**Solution:**
```bash
conan profile detect --force
```

#### Issue: "C++20 features not available"

**Problem:** Compiler doesn't support C++20 or isn't detected correctly

**Solution:**
```bash
# Check compiler version
g++ --version    # Should be 10.0 or higher
clang++ --version # Should be 12.0 or higher

# Explicitly specify compiler
export CXX=g++-11  # or clang++-14
cmake -B Build -S . -DCMAKE_CXX_COMPILER=$CXX
```

#### Issue: "Missing dependencies during Conan install"

**Problem:** System packages required by Conan dependencies are missing

**Solution:**
```bash
# Add the system package manager mode
conan install . \
  --output-folder=Build \
  --build=missing \
  -c tools.system.package_manager:mode=install \
  -c tools.system.package_manager:sudo=True
```

#### Issue: "SFML or OpenGL errors"

**Problem:** Missing graphics libraries

**Solution:**
```bash
# Linux (Ubuntu/Debian)
sudo apt install libgl1-mesa-dev libglu1-mesa-dev libx11-dev \
                 libxrandr-dev libxcursor-dev libxi-dev libudev-dev

# Fedora/RHEL
sudo dnf install mesa-libGL-devel mesa-libGLU-devel libX11-devel \
                 libXrandr-devel libXcursor-devel libXi-devel systemd-devel
```

#### Issue: "Permission denied" errors with Conan

**Problem:** Attempting to run Conan with sudo

**Solution:**
```bash
# NEVER use sudo with Conan commands
# Instead, ensure your user has proper permissions
pipx install conan  # Installs to user directory
conan profile detect --force
```

#### Issue: "Build fails with linker errors"

**Problem:** Inconsistent build state or missing libraries

**Solution:**
```bash
# Clean rebuild
rm -rf Build
./Scripts/Build.sh --clean

# Or manually
mkdir Build
conan install . --output-folder=Build --build=missing
cmake -B Build -S .
cmake --build Build --parallel
```

### Runtime Issues

#### Issue: "Server fails to start - Port already in use"

**Problem:** Another process is using port 4242

**Solution:**
```bash
# Find the process
lsof -i :4242  # Linux/macOS
netstat -ano | findstr :4242  # Windows

# Kill the process or use different port
./RTypeGameServer --port 4243
```

#### Issue: "Client cannot connect to server"

**Problem:** Firewall blocking connection or wrong host/port

**Solution:**
```bash
# Check firewall (Linux)
sudo ufw allow 4242/tcp
sudo ufw allow 4242/udp

# Test connection
telnet localhost 4242

# Specify correct host
./RTypeGameClient --host 192.168.1.100 --port 4242
```

#### Issue: "Graphics rendering issues or black screen"

**Problem:** OpenGL driver or compatibility issues

**Solution:**
```bash
# Check OpenGL version
glxinfo | grep "OpenGL version"  # Linux

# Update graphics drivers
# Linux: Use your distribution's driver manager
# Windows: Update from manufacturer website (NVIDIA, AMD, Intel)
# macOS: Update system via Software Update

# Run in software rendering mode (fallback)
LIBGL_ALWAYS_SOFTWARE=1 ./RTypeGameClient  # Linux
```

#### Issue: "VR application crashes or HMD not detected"

**Problem:** OpenVR/SteamVR not properly configured

**Solution:**
```bash
# Ensure SteamVR is running
# Check VR headset connection
# Verify OpenVR runtime is installed

# Test OpenVR installation
steam steam://rungameid/250820  # Launch SteamVR

# Check OpenVR paths
echo $OPENVR_API_PATH
```

### Getting Help

If you encounter issues not covered here:

1. **Check Build Logs**: Review complete error messages in build output
2. **Search Issues**: Check the [GitHub Issues](https://github.com/mallory-scotton/rtype/issues) page
3. **Enable Verbose Logging**:
   ```bash
   cmake -B Build -S . -DCMAKE_VERBOSE_MAKEFILE=ON
   cmake --build Build --verbose
   ```
4. **Report Bugs**: Open a new issue with:
   - Operating system and version
   - Compiler version
   - Complete error message
   - Steps to reproduce
