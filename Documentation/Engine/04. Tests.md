# 🧪 Tests

## Overview

The TKD Engine employs comprehensive unit testing to ensure code quality, reliability, and maintainability. Tests are written using the Catch2 testing framework and cover core engine systems, utilities, and network components.

## Testing Framework

### Catch2
- **Version**: Latest stable release via Conan
- **Features**: BDD-style testing, automatic test discovery, rich assertions
- **Integration**: CMake-based test discovery and execution

## Running Tests

### Build with Tests
```bash
# Tests are enabled by default
cmake -B Build -S . -DBUILD_TESTS=ON
cmake --build Build --config Release
```

### Execute Tests
```bash
# Run all tests
./Build/bin/TKDEngineTests

# Run with verbose output
./Build/bin/TKDEngineTests -v

# Run specific test suite
./Build/bin/TKDEngineTests "[network]"

# Run specific test case
./Build/bin/TKDEngineTests "BinaryReader should read integers"
```

### Test Output
- **Success**: Green output with test counts
- **Failure**: Red output with detailed failure information
- **Coverage**: Integration with code coverage tools (optional)

## Writing Tests

### Test File Structure
```cpp
#include <catch2/catch_test_macros.hpp>
#include <Engine/Component/ToTest.hpp>

TEST_CASE("ComponentName functionality", "[component]") {
    SECTION("should handle basic operations") {
        // Arrange
        // Act
        // Assert
    }
}
```

### Best Practices
- **Descriptive Names**: Clear test and section names
- **Single Responsibility**: Each test focuses on one behavior
- **Arrange-Act-Assert**: Standard testing pattern
- **Edge Cases**: Test boundary conditions and error paths
- **Mocking**: Use test doubles for external dependencies

### Test Naming Convention
- **Files**: `ComponentName.Tests.cpp`
- **Test Cases**: Descriptive sentences starting with "should"
- **Tags**: `[category]` for test filtering

## Test Maintenance

### Adding New Tests
1. Create test file in appropriate directory
2. Include necessary headers
3. Write test cases using Catch2 macros
4. Add to CMake build system (automatic discovery)

### Updating Tests
- **Refactor**: Update tests when code changes
- **Remove**: Delete obsolete tests
- **Add**: Cover new functionality immediately

### Test Dependencies
- **Catch2**: Automatically managed by Conan
- **Engine Headers**: Include via relative paths
- **Test Data**: Use fixtures for complex setup
