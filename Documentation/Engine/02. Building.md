# 🛠️ Building

## Overview

The TKD Engine uses CMake as its build system with Conan for dependency management. The build process supports multiple configurations to create different types of executables:

- **Debug Engine**: Engine library + main executable (for development/testing)
- **Released Game**: Engine library + game library + main executable (production builds)
- **Server/Client Modes**: Engine libraries exist in both server (headless) and client (with graphics) variants

## Prerequisites

### Required Tools
- **CMake** 3.21 or later
- **C++ Compiler** (GCC 9+, Clang 10+, MSVC 2019+ with C++20 support)
- **Conan** 2.0+ (installed via pipx)
- **Git** (for cloning and hooks)

### Dependencies
All dependencies are managed automatically by Conan:
- **SFML** 2.6.1+ (for graphics, audio, networking)
- **Catch2** 3.10.0+ (for testing)
- **ImGui** 1.91.8+ (for debugging UI)
- **Asio** 1.36.1+ (networking backend)
- **Zlib** 1.3.1+ (compression)

## Build Process

### Quick Start

#### Linux/macOS
```bash
./Scripts/Build.sh
```

#### Windows
```cmd
Scripts/Build.bat
```

### Manual Build Steps

1. **Install Conan**:
   ```bash
   pipx install conan
   conan profile detect --force
   ```

2. **Install Dependencies**:
   ```bash
   conan install . --output-folder=Build --build=missing --settings=build_type=Release
   ```

3. **Configure CMake**:
   ```bash
   cmake -B Build -S . -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=Build/build/Release/generators/conan_toolchain.cmake
   ```

4. **Build**:
   ```bash
   cmake --build Build --config Release -j$(nproc)
   ```

## Build Configurations

### Engine Library Variants

The engine is built as shared libraries in two modes:

#### TKDEngineClient (Client Mode)
- **Includes**: Graphics, audio, windowing, networking
- **Define**: `TKD_ENGINE_WITH_GRAPHICS`
- **Use**: For client applications requiring visual output

#### TKDEngineServer (Server Mode)
- **Includes**: Networking only (headless)
- **Use**: For server applications without graphics dependencies

### Executable Types

#### Debug Engine
**Composition**: Engine library + Main.cpp
- **Purpose**: Development and testing of engine features
- **Executables**:
  - `TKDEngineClient` (client mode with graphics)
  - `TKDEngineServer` (server mode headless)
- **Use**: Run engine without game logic for debugging core systems

#### Released Game
**Composition**: Engine library + Game library + Main.cpp
- **Purpose**: Production game builds
- **Executables**:
  - `RTypeGameClient` (full client game)
  - `RTypeGameServer` (dedicated server)
- **Use**: Complete game applications ready for distribution

## Directory Structure

```

│   ├── RTypeGameServer

│   └── TKDEngineServer

│   ├── libRTypeGameServer.so
│   ├── libTKDEngineClient.so
│   └── libTKDEngineServer.so

```

## Running the Built Applications

### Debug Engine

```bash
./Build/bin/TKDEngineClient

# Server mode (headless)
./Build/bin/TKDEngineServer
```

### Released Game
```bash
# Client game
./Build/bin/RTypeGameClient

# Server game
./Build/bin/RTypeGameServer
```

## Build Options

### CMake Options
- `CMAKE_BUILD_TYPE`: Release/Debug
- `BUILD_TESTS`: Enable/disable unit tests (default: ON)

### Conan Profiles
- Automatically detects compiler and system
- Supports cross-compilation
- Manages system package installation

## Platform-Specific Notes

### Linux
- Uses system package managers (apt, dnf, etc.) via Conan
- Supports GCC and Clang
- Libraries output as `.so` files

### macOS
- Uses Homebrew for dependencies
- Supports Clang
- Libraries output as `.dylib` files

### Windows
- Uses MSVC by default
- Supports MinGW as alternative
- Libraries output as `.dll` files

## Troubleshooting

### Common Issues

1. **Conan Profile Detection Fails**
   ```bash
   conan profile detect --force
   ```

2. **CMake Toolchain Not Found**
   - Ensure Conan install completed successfully
   - Check `Build/build/Release/generators/conan_toolchain.cmake` exists

3. **Missing Dependencies**
   - Run build script with `--installer=<package_manager>`
   - Or install manually: SFML development packages

4. **Compiler Errors**
   - Ensure C++20 support
   - Check CMake version >= 3.21

### Clean Build
```bash
rm -rf Build
# Then rerun build process
```

## Development Workflow

1. **Initial Setup**: Run build script once
2. **Code Changes**: Modify source files
3. **Incremental Build**: `cmake --build Build`
4. **Testing**: Run executables from `Build/bin/`
5. **Full Rebuild**: Delete Build directory and rebuild

## CI/CD Integration

The build system is designed for automation:
- Conan handles cross-platform dependencies
- CMake presets support different configurations
- Build scripts work in CI environments
- Output structure consistent across platforms
