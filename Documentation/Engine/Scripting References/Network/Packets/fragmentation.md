# Fragmentation Packets

## Overview

The fragmentation system in the TKD Engine allows large packets that exceed the maximum UDP packet size (~1500 bytes) to be split into smaller fragments, transmitted reliably, and reassembled at the destination. This system consists of two packet types and the `FFragmentManager` that coordinates the process.

This ensures that large data (such as snapshots, large RPCs, or asset data) can be transmitted reliably over UDP without packet loss issues.

---

## Fragment Packet

### Overview

The `Fragment` packet represents a single piece of a larger message that has been split for transmission. Multiple fragments with the same `PackageID` are reassembled into the original packet.

### Fields

#### `UInt32 PackageID`

Unique identifier for the entire fragmented message.

- **Use:** Groups all fragments belonging to the same original packet.
- **Value:** Generated by `FFragmentManager` when fragmenting a packet.

#### `UInt8 SequenceID`

The sequence number of this specific fragment within the package.

- **Range:** 0 to `FragmentCount - 1`
- **Use:** Determines the order for reassembly.

#### `UInt8 FragmentCount`

The total number of fragments in this package.

- **Use:** Indicates when all fragments have been received for reassembly.
- **Example:** If a packet is split into 5 fragments, `FragmentCount` will be 5 for all fragments.

#### `std::vector<Byte> data`

The actual data payload for this fragment.

- **Size:** Maximum 512 bytes per fragment (defined by `MAX_FRAGMENT_SIZE`).
- **Use:** Contains a portion of the original serialized packet data.

### Usage

#### Automatic Fragmentation

The `FFragmentManager` automatically handles fragmentation when sending large packets:

```cpp
// Large packet that needs fragmentation
Packets::Snapshot largeSnapshot;
largeSnapshot.SetupFromWorld(*world);  // Assume this is > 1500 bytes

// Serialize the packet
std::vector<Byte> serializedData;
FBinaryWriter writer(serializedData);
largeSnapshot.Serialize(writer);

// FragmentManager automatically fragments if needed
if (serializedData.size() > MAX_UDP_SIZE) {
    UUID fragmentID = FragmentManager::Get().SendFullTransmission(
        serializedData,
        destinations,
        networkBase
    );
}
```

#### Manual Fragment Handling (Advanced)

While typically automatic, you can work with fragments directly:

```cpp
networkBase.RegisterPacketHandler<Packets::Fragment>(
    [](const Packets::Fragment& fragment, const FEndpoint& sender) {
        // FragmentManager automatically processes incoming fragments
        FragmentManager::Get().ProcessFragment(fragment, sender, networkBase);
    }
);
```

### Notes

- Fragments are sent reliably with acknowledgment and retransmission.
- Maximum fragment size is 512 bytes to ensure compatibility with most networks.
- If a single fragment is lost, only that fragment is retransmitted (selective retransmission).
- Fragments are automatically cleaned up after successful reassembly or timeout.

## FragmentAcknowledgment Packet

### Overview

The `FragmentAcknowledgment` packet is sent by the receiver to confirm receipt of a specific fragment. This enables reliable transmission with selective retransmission of only the missing fragments.

### Fields

#### `UInt32 PackageID`

The ID of the complete package being acknowledged.

- **Use:** Matches the `PackageID` from the `Fragment` packet.
- **Purpose:** Identifies which fragmented message this ACK belongs to.

#### `UInt32 FragmentID`

The sequence number of the specific fragment being acknowledged.

- **Use:** Matches the `SequenceID` from the `Fragment` packet.
- **Purpose:** Tells the sender which specific fragment was received successfully.

### Usage

#### Automatic Acknowledgment

The receiver automatically sends acknowledgments when fragments are received:

```cpp
// In FFragmentManager::ProcessFragment
void ProcessFragment(
    const IPacket& packet,
    const FEndpoint& sender,
    FNetworkBase* networkBase
) {
    // Parse fragment
    auto& fragment = static_cast<const Packets::Fragment&>(packet);
    
    // Store fragment
    StoreFragment(fragment, sender);
    
    // Send acknowledgment
    Packets::FragmentAcknowledgment ack;
    ack.PackageID = fragment.PackageID;
    ack.FragmentID = fragment.SequenceID;
    networkBase->SendPacket(ack, sender);
}
```

#### Sender Side (Handling ACKs)

The sender tracks which fragments have been acknowledged:

```cpp
networkBase.RegisterPacketHandler<Packets::FragmentAcknowledgment>(
    [](const Packets::FragmentAcknowledgment& ack, const FEndpoint& sender) {
        // Find the fragment entry
        auto* entry = FragmentManager::Get().FindFragmentEntry(ack.PackageID);
        if (entry && ack.FragmentID < entry->chunks.size()) {
            // Mark chunk as received from this endpoint
            entry->chunks[ack.FragmentID].statuses[sender].received = true;
            
            // Check if all chunks are ACK'd from all destinations
            if (IsFullyAcknowledged(entry)) {
                FragmentManager::Get().MarkFragmentForDeletion(entry->id);
            }
        }
    }
);
```

### Notes

- Each fragment must be individually acknowledged.
- ACKs are tracked per endpoint (allows multicasting fragments to multiple clients).
- If an ACK is not received within `ACK_TIMEOUT` (500ms), the fragment is automatically retransmitted.
- The sender only retransmits fragments that were not acknowledged, saving bandwidth.

## Fragmentation Flow

### Sending Large Packets

```
1. Sender: Large packet needs to be sent (e.g., 3000 bytes)
   └─> FragmentManager.SendFullTransmission()

2. FragmentManager: Split into fragments
   ├─> Fragment 0: bytes 0-511 (PackageID=123, SequenceID=0, FragmentCount=6)
   ├─> Fragment 1: bytes 512-1023 (PackageID=123, SequenceID=1, FragmentCount=6)
   ├─> Fragment 2: bytes 1024-1535 (PackageID=123, SequenceID=2, FragmentCount=6)
   ├─> Fragment 3: bytes 1536-2047 (PackageID=123, SequenceID=3, FragmentCount=6)
   ├─> Fragment 4: bytes 2048-2559 (PackageID=123, SequenceID=4, FragmentCount=6)
   └─> Fragment 5: bytes 2560-2999 (PackageID=123, SequenceID=5, FragmentCount=6)

3. Network: Send all fragments over UDP

4. Receiver: Receives fragments (possibly out of order)
   ├─> Fragment 0 ✓ → Send ACK(PackageID=123, FragmentID=0)
   ├─> Fragment 2 ✓ → Send ACK(PackageID=123, FragmentID=2)
   ├─> Fragment 1 ✗ (lost in transit)
   ├─> Fragment 3 ✓ → Send ACK(PackageID=123, FragmentID=3)
   ├─> Fragment 4 ✓ → Send ACK(PackageID=123, FragmentID=4)
   └─> Fragment 5 ✓ → Send ACK(PackageID=123, FragmentID=5)

5. Sender: After ACK_TIMEOUT (500ms), retransmit Fragment 1
   └─> Send Fragment 1 again

6. Receiver: Receives retransmitted Fragment 1
   └─> Send ACK(PackageID=123, FragmentID=1)

7. FragmentManager: All fragments received
   ├─> Sort fragments by SequenceID
   ├─> Merge data: [0-511] + [512-1023] + ... + [2560-2999]
   ├─> Deserialize original packet
   ├─> Process packet through normal packet handlers
   └─> Delete fragment entry

8. Sender: All ACKs received
   └─> Delete fragment entry
```

### Retransmission Strategy

**Selective Retransmission:** Only missing fragments are resent, not the entire package.

```
Time 0ms:   Send all 6 fragments
Time 100ms: Receive ACKs for fragments 0, 2, 3, 4, 5
Time 500ms: ACK timeout for fragment 1
            └─> Resend only fragment 1
Time 600ms: Receive ACK for fragment 1
            └─> Complete! Clean up.
```

## Configuration

### Constants (in `FFragmentManager`)

| Constant | Value | Description |
|----------|-------|-------------|
| `MAX_FRAGMENT_SIZE` | 512 bytes | Maximum payload size per fragment |
| `ACK_TIMEOUT` | 500ms | Time to wait for ACK before retransmission |
| `DELETION_TIMEOUT` | 1000ms | Time to keep completed fragments before cleanup |

### Customization

You can adjust these values in `FFragmentManager.hpp`:

```cpp
class FragmentManager {
public:
    static constexpr SizeT MAX_FRAGMENT_SIZE = 512;      // Increase for higher bandwidth
    static constexpr Float32 ACK_TIMEOUT = 0.5f;         // Increase for high-latency networks
    static constexpr Float32 DELETION_TIMEOUT = 1.0f;    // Increase for debugging
};
```

## Performance Considerations

### Bandwidth Efficiency

- **Overhead per fragment:** ~10 bytes (PackageID + SequenceID + FragmentCount + packet header)
- **Example:** 3000-byte packet → 6 fragments × 10 bytes = 60 bytes overhead (~2%)
- **ACK overhead:** 8 bytes per fragment ACK

### When to Use

✅ **Use fragmentation for:**
- Snapshots with many actors (> 1500 bytes)
- Large RPC calls with substantial data
- Asset transfers
- Bulk property replication

❌ **Avoid fragmentation for:**
- Small frequent packets (< 500 bytes)
- Time-critical data (adds latency due to reassembly)
- Unreliable data that doesn't need guaranteed delivery

### Best Practices

1. **Batch small updates** into larger packets to reduce per-packet overhead
2. **Compress large data** before fragmentation to reduce fragment count
3. **Monitor fragment metrics** (retransmission rate) to detect network issues
4. **Use delta compression** (like snapshots) to reduce packet size before fragmentation
