# 📦 Dependencies

## Overview

The TKD Engine uses several external libraries to provide core functionality across graphics, networking, audio, testing, and VR support. All dependencies are managed through **Conan** (a C++ package manager) to ensure consistent builds across platforms.

This document provides a comprehensive overview of each dependency, explaining what it is, why we chose it, and how it's used in the engine.

---

## Dependency Management

### Conan Package Manager

**Version:** Latest (via pipx/pip)
**Purpose:** C++ package manager for dependency management

We use Conan to:
- Automatically download and build dependencies
- Ensure consistent library versions across all platforms
- Simplify the build process for developers
- Handle transitive dependencies automatically

## Core Dependencies

### 1. SFML (Simple and Fast Multimedia Library)

**Package:** `sfml/2.6.2`
**License:** zlib/png license
**Website:** https://www.sfml-dev.org/

#### What is SFML?

SFML is a comprehensive multimedia library providing simple interfaces for graphics, audio, windowing, networking, and system utilities. It's written in C++ and designed to be beginner-friendly while remaining powerful.

#### Why We Use It

**Prior Experience:** The team has extensive prior experience using SFML for graphical applications and game development. This familiarity allows us to:
- Develop faster with a known API
- Leverage existing knowledge and best practices
- Reduce learning curve for new team members
- Build on proven solutions from previous projects

**Technical Benefits:**
- Clean, intuitive object-oriented API
- Cross-platform support (Windows, Linux, macOS)
- Hardware-accelerated rendering via OpenGL
- Integrated audio system
- Built-in windowing and input handling
- Active community and excellent documentation

#### Where We Use It

**Renderer Module:**
- Window creation and management (`Engine/Source/Engine/Renderer/SFML/Window.hpp`)
- 2D rendering (`Engine/Source/Engine/Renderer/SFML/Renderer.cpp`)
- Texture loading and management (`Engine/Source/Engine/Renderer/SFML/Texture.hpp`)
- Shader management (`Engine/Source/Engine/Renderer/SFML/Shader.hpp`)
- Render targets (`Engine/Source/Engine/Renderer/SFML/RenderTarget.hpp`)

**Audio Module:**
- Audio playback (`Engine/Source/Engine/Audio/SFML/AudioManager.hpp`)
- Audio sources and listeners (`Engine/Source/Engine/Audio/SFML/AudioSource.hpp`)
- Audio streaming (`Engine/Source/Engine/Audio/SFML/AudioStream.hpp`)
- Audio effects (`Engine/Source/Engine/Audio/SFML/AudioEffect.hpp`)
- Audio buffers (`Engine/Source/Engine/Audio/SFML/AudioBuffer.hpp`)

**Components Used:**
- `sfml-graphics` - 2D graphics rendering
- `sfml-window` - Window and input handling
- `sfml-audio` - Audio playback and processing
- `sfml-system` - System utilities (time, threads)
- `sfml-network` - Networking (minimal usage, we primarily use ASIO)

### 2. ASIO (Asynchronous I/O)

**Package:** `asio/1.36.0`
**License:** Boost Software License
**Website:** https://think-async.com/Asio/

#### What is ASIO?

ASIO (not to be confused with the audio API) is a cross-platform C++ library for network and low-level I/O programming. It provides asynchronous I/O operations with a consistent interface across different platforms.

#### Why We Use It

**UDP Requirement:** The project specification requires using **UDP** (User Datagram Protocol) instead of TCP. UDP provides:
- Lower latency (no connection handshaking)
- More freedom for custom packet management
- Better control over reliability mechanisms
- Reduced overhead for fast-paced networked games

**Technical Benefits:**
- Header-only library (easy integration)
- Cross-platform async I/O
- Excellent UDP socket support
- Scalable for many concurrent connections
- Proactor pattern for efficient async operations
- Timer support for timeout management
- Well-documented and actively maintained

**Why Not SFML Network?**
While SFML includes networking capabilities, ASIO provides:
- More advanced UDP control
- Better async patterns for game servers
- More flexible packet handling
- Superior performance for high-throughput scenarios

#### Where We Use It

**Network Module:**
- UDP socket management (`Engine/Source/Engine/Network/Asio.hpp`)
- Asynchronous packet sending/receiving (`Engine/Source/Engine/Network/FNetworkClient.cpp`)
- Connection management (`Engine/Source/Engine/Network/FConnectionInformation.hpp`)
- Server and client networking (`Engine/Source/Engine/Network/FNetworkServer.cpp`)
- Network timing and timeouts

**Key Classes:**
- `asio::io_context` - Core I/O event loop
- `asio::ip::udp::socket` - UDP socket operations
- `asio::ip::udp::endpoint` - Network endpoint representation
- `asio::steady_timer` - Timeout and timing operations

### 3. nlohmann/json

**Package:** `nlohmann_json/3.12.0`
**License:** MIT
**Website:** https://github.com/nlohmann/json

#### What is nlohmann/json?

A modern, header-only C++ library for JSON parsing and serialization. It provides intuitive JSON manipulation with STL-like syntax.

#### Why We Use It

**Configuration and Data:**
- Engine configuration files (settings, preferences)
- Asset metadata (levels, animations, sprites)
- Save game data
- Network protocol data (when human-readable format needed)

**Technical Benefits:**
- Intuitive syntax (similar to Python/JavaScript JSON handling)
- Header-only (easy integration)
- STL container compatibility
- Automatic type conversions
- Excellent error messages
- Wide adoption in C++ community

#### Where We Use It

**Config Module:**
- Type definitions (`Engine/Source/Engine/Config/Types.hpp`)
- Engine settings serialization
- Configuration file parsing

**Usage Pattern:**
```cpp
// Parse JSON
nlohmann::json config = nlohmann::json::parse(configFile);

// Access values
int width = config["window"]["width"];
std::string title = config["window"]["title"];

// Serialize to JSON
nlohmann::json settings;
settings["graphics"]["vsync"] = true;
settings["audio"]["volume"] = 0.8f;
```

## Development and Testing Dependencies

### 10. Catch2

**Package:** `catch2/3.10.0`
**License:** Boost Software License
**Website:** https://github.com/catchorg/Catch2

#### What is Catch2?

Catch2 is a modern, header-only C++ testing framework for unit tests, TDD, and BDD. It provides a natural language-like syntax for writing tests.

#### Why We Use It

**Unit Testing:**
- Test-driven development support
- Comprehensive assertion library
- BDD-style test organization
- Excellent error reporting
- Minimal setup required

**Technical Benefits:**
- Header-only (easy integration)
- Natural syntax (readable tests)
- Test discovery and filtering
- Benchmarking support
- Integration with CTest
- Wide adoption in C++ community

#### Where We Use It

**Testing:**
- Core module tests (`Engine/Tests/Core/`)
  - Math tests (TVector2, TVector3, TVector4)
  - Container tests (FString)
  - Utility tests (Singleton, EventEmitter, Args)
- Network module tests (`Engine/Tests/Network/`)
- Test runner (`Engine/Tests/Main.cpp`)

**Example Tests:**
```cpp
#include <catch2/catch_test_macros.hpp>
#include <catch2/catch_approx.hpp>

TEST_CASE("Vector operations", "[math][vector]") {
    FVector3 v1(1.0f, 2.0f, 3.0f);
    FVector3 v2(4.0f, 5.0f, 6.0f);

    SECTION("Addition") {
        FVector3 result = v1 + v2;
        REQUIRE(result.x == Catch::Approx(5.0f));
        REQUIRE(result.y == Catch::Approx(7.0f));
        REQUIRE(result.z == Catch::Approx(9.0f));
    }
}
```

## Tool Dependencies

### 11. zlib

**Package:** `zlib/1.3.1`
**License:** zlib License
**Website:** https://www.zlib.net/

#### What is zlib?

zlib is a lossless data compression library implementing the DEFLATE algorithm. It's widely used for file compression and is the basis for formats like PNG and ZIP.

#### Why We Use It

**Asset Embedding:**
We use zlib in our **TKDEmbed** tool to compress game assets before embedding them into executables or data files.

**Benefits:**
- Reduces binary size
- Fast decompression at runtime
- Industry-standard compression
- Excellent compression ratios
- Minimal memory overhead

#### Where We Use It

**TKDEmbed Tool:**
- Compressing assets before embedding (`Tools/TKDEmbed/Source/Main.cpp`)
- Creating compressed header files from asset files
- Reducing distribution size

**Process:**
1. Asset files are read
2. Compressed using zlib (Z_BEST_COMPRESSION)
3. Embedded into C++ headers as byte arrays
4. Decompressed at runtime when needed

**Code Example:**
```cpp
#include <zlib.h>

// Compress asset data
uLongf compressedSize = compressBound(fileSize);
std::vector<uint8_t> compressedBuffer(compressedSize);

int result = compress2(
    compressedBuffer.data(),
    &compressedSize,
    buffer.data(),
    fileSize,
    Z_BEST_COMPRESSION
);
```

## Dependency Rationale Summary

### Key Design Decisions

1. **SFML for Graphics:** Chosen due to team familiarity and proven track record. Provides all-in-one multimedia solution.

2. **ASIO for Networking:** Required for UDP support with better control than SFML's TCP-focused networking. Provides async I/O patterns suitable for game servers.

3. **Header-Only Libraries:** Preferred where possible (nlohmann/json, ASIO, Catch2) for easier integration and faster compilation in small projects.

4. **Modern Versions:** Using latest stable versions to benefit from bug fixes, performance improvements, and modern C++20 features.

5. **Cross-Platform:** All dependencies support Windows, Linux, and macOS, ensuring engine portability.

6. **Permissive Licenses:** All dependencies use permissive licenses (MIT, BSD, Boost, zlib) allowing commercial use.

## Installation and Setup

All dependencies are automatically managed by Conan. To install:

```bash
# Install Conan
pipx install conan

# Create profile
conan profile detect --force

# Install all dependencies
conan install . --output-folder=Build --build=missing \
    --settings=build_type=Release --settings=compiler.cppstd=20 \
    -c tools.system.package_manager:mode=install
```

See the main [README.md](/README.md) for complete build instructions.

## Troubleshooting Dependencies

### Common Issues

**SFML not found:**
```bash
# Reinstall SFML through Conan
conan install . --output-folder=Build --build=sfml --build=missing
```

**OpenGL not available:**
- **Linux:** Install mesa development packages
- **Windows:** Update graphics drivers
- **macOS:** Ensure Xcode Command Line Tools installed

**OpenVR missing (optional):**
```bash
# Install SteamVR
# Or disable VR support by removing openvr from conanfile.py
```

**Catch2 version conflicts:**
```bash
# Use specific version
conan install . --output-folder=Build --build=missing \
    -o catch2:version=3.10.0
```
