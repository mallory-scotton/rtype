# Audio Module Documentation

## Overview

The Audio module provides a comprehensive audio system for the TKD Engine, enabling 2D and 3D sound playback, streaming, effects processing, and spatial audio. The module is built on an interface-based architecture with SFML as the concrete implementation, allowing for potential replacement with other audio backends.

### Key Features

- **Interface-Based Design**: Clean separation between interface and implementation
- **2D & 3D Audio**: Support for both standard and spatial audio playback
- **Streaming Support**: Efficient streaming for large audio files (music)
- **Buffer Management**: Caching and reuse of loaded audio buffers
- **Audio Effects**: Built-in support for reverb, echo, chorus, distortion, and filters
- **Doppler Effect**: Realistic pitch shifting for moving audio sources
- **Multiple Attenuation Models**: Inverse, linear, and exponential distance attenuation
- **Thread-Safe**: Mutex-protected operations for multi-threaded environments
- **Asset Integration**: Direct loading from engine asset system
- **Device Management**: Query and select audio output devices

---

## Architecture

### Interface Layer

The Audio module defines six core interfaces that establish the contract for audio functionality:

```
Engine/Source/Engine/Audio/
├── Interfaces/
│   ├── IAudioManager.hpp    # Central audio system manager
│   ├── IAudioBuffer.hpp     # Audio data storage
│   ├── IAudioSource.hpp     # Audio playback source/emitter
│   ├── IAudioStream.hpp     # Streaming audio playback
│   ├── IAudioListener.hpp   # 3D audio listener (camera/player)
│   └── IAudioEffect.hpp     # Audio effects processing
└── SFML/
    ├── AudioManager.hpp/cpp  # SFML implementation
    ├── AudioBuffer.hpp/cpp   # SFML sound buffer wrapper
    ├── AudioSource.hpp/cpp   # SFML sound wrapper
    ├── AudioStream.hpp/cpp   # SFML music wrapper
    ├── AudioListener.hpp/cpp # SFML listener wrapper
    └── AudioEffect.hpp/cpp   # SFML effect wrapper
```

### Design Philosophy

1. **Interface Segregation**: Each component has a focused responsibility
2. **Implementation Hiding**: Users interact with interfaces, not concrete types
3. **Factory Pattern**: AudioManager creates all audio objects
4. **Resource Management**: Smart pointers for automatic memory management
5. **Thread Safety**: Mutex protection for concurrent access

## Audio Manager

The **AudioManager** is the central hub of the audio system, responsible for:
- Creating and managing audio resources (buffers, sources, streams, effects)
- Loading and caching audio data
- Providing convenience methods for playing sounds
- Managing the audio listener
- Updating audio state (Doppler effect, source cleanup)
- Device management

### Interface: `IAudioManager`

#### Update Loop
The `Update()` method performs two critical tasks:

1. **Source Cleanup**: Removes stopped, non-looping sources to prevent memory leaks
```cpp
m_sources.erase(
    std::remove_if(m_sources.begin(), m_sources.end(),
        [](const auto& source) {
            return source->GetState() == EAudioSourceState::Stopped && 
                   !source->IsLooping();
        }),
    m_sources.end()
);
```

2. **Doppler Effect Application**: Updates pitch for moving 3D sources
```cpp
for (auto& source : m_sources)
{
    if (source->IsSpatial() && source->GetDopplerFactor() > 0.0f)
    {
        ApplyDopplerEffect(source.get(), deltaTime);
    }
}
```

#### Buffer Caching
The manager caches loaded buffers by file path to avoid redundant disk I/O:

```cpp
TSharedPtr<IAudioBuffer> AudioManager::LoadBuffer(const FilePath& filePath)
{
    std::lock_guard<std::mutex> lock(m_mutex);
    
    // Check cache first
    auto it = m_buffers.find(filePath.string());
    if (it != m_buffers.end()) { return it->second; }
    
    // Load and cache new buffer
    auto buffer = CreateBuffer();
    if (buffer->LoadFromFile(filePath))
    {
        m_buffers[filePath.string()] = buffer;
        return buffer;
    }
    return nullptr;
}
```

#### Convenience Play Methods
The `PlaySound()` and `PlaySound3D()` methods simplify one-shot sound effects:

```cpp
void AudioManager::PlaySound(const FilePath& filePath, Float32 volume, Bool loop)
{
    auto buffer = LoadBuffer(filePath);
    if (!buffer) { return; }
    
    auto source = CreateSource();
    source->SetBuffer(buffer);
    source->SetVolume(volume);
    source->SetLooping(loop);
    source->SetSpatial(false);  // 2D sound
    source->Play();
}

void AudioManager::PlaySound3D(const FilePath& filePath, const FVector3& position, 
                                Float32 volume, Bool loop)
{
    auto buffer = LoadBuffer(filePath);
    if (!buffer) { return; }
    
    auto source = CreateSource();
    source->SetBuffer(buffer);
    source->SetPosition(position);
    source->SetVolume(volume);
    source->SetMinDistance(1.0f);
    source->SetMaxDistance(100.0f);
    source->SetRolloffFactor(1.0f);
    source->SetLooping(loop);
    source->SetSpatial(true);  // 3D sound
    source->Play();
}
```

### Attenuation Models

The attenuation model determines how volume decreases with distance:

1. **None**: No attenuation, constant volume regardless of distance
   ```cpp
   source->SetAttenuationModel(EAttenuationModel::None);
   ```

2. **Inverse**: Volume proportional to 1/distance (realistic)
   ```cpp
   source->SetAttenuationModel(EAttenuationModel::Inverse);
   source->SetRolloffFactor(1.0f);  // Standard falloff
   ```
   Formula: `volume = minDistance / (minDistance + rolloff * (distance - minDistance))`

3. **Linear**: Linear interpolation between min and max distance
   ```cpp
   source->SetAttenuationModel(EAttenuationModel::Linear);
   source->SetMinDistance(10.0f);
   source->SetMaxDistance(100.0f);
   ```

4. **Exponential**: Exponential decay (fastest falloff)
   ```cpp
   source->SetAttenuationModel(EAttenuationModel::Exponential);
   ```

### SFML Limitations

Some advanced features are not natively supported by SFML and are emulated:
- **Velocity**: Stored internally, used for manual Doppler calculation
- **Direction/Cones**: Not supported (no directional audio)
- **Min/Max Distance**: Min distance not used by SFML; max distance not enforced

### Buffer vs Stream: When to Use Each

| Feature              | AudioBuffer + AudioSource | AudioStream |
|----------------------|--------------------------|-------------|
| **Memory Usage**     | Full file loaded in RAM  | Streamed chunks |
| **CPU Usage**        | Low                      | Higher (decoding on-the-fly) |
| **Latency**          | Instant playback         | Slight delay on open |
| **Multiple Instances** | Yes (multiple sources) | No (one instance per stream) |
| **Use Cases**        | Sound effects, UI sounds | Background music, ambient |
| **Typical Size**     | < 1 MB                   | > 1 MB |

**Rule of Thumb**: Use **AudioBuffer** for short, frequently-played sounds. Use **AudioStream** for long, rarely-repeated sounds.

## 3D Audio System

The 3D audio system provides realistic spatial audio with distance attenuation, Doppler effect, and listener-relative positioning.

### Doppler Effect

The Doppler effect simulates pitch changes for moving sound sources (e.g., a car passing by).

#### Implementation

The `AudioManager::ApplyDopplerEffect()` method calculates pitch shift based on:
- Source position and velocity
- Listener position and velocity
- Speed of sound
- Doppler factors

```cpp
void AudioManager::ApplyDopplerEffect(IAudioSource* source, Float32 deltaTime)
{
    FVector3 sourcePos = source->GetPosition();
    FVector3 listenerPos = m_listener.GetPosition();
    FVector3 toSource = sourcePos - listenerPos;
    Float32 distance = toSource.Length();

    if (distance < 0.001f)
    {
        source->SetPitch(1.0f);
        return;
    }

    // Get or create doppler state for this source
    auto& state = m_dopplerStates[source];

    // Calculate velocity from position change if not explicitly set
    FVector3 sourceVel = source->GetVelocity();
    FVector3 listenerVel = m_listener.GetVelocity();

    if (sourceVel.Length() < 0.001f && deltaTime > 0.0f)
    {
        sourceVel = (sourcePos - state.lastPosition) * (1.0f / deltaTime);
    }

    // Calculate radial velocity (velocity along the line connecting listener and source)
    FVector3 toSourceNorm = toSource.Normalized();
    Float32 sourceRadialSpeed = sourceVel.x * toSourceNorm.x + 
                                sourceVel.y * toSourceNorm.y + 
                                sourceVel.z * toSourceNorm.z;
    Float32 listenerRadialSpeed = listenerVel.x * toSourceNorm.x + 
                                   listenerVel.y * toSourceNorm.y + 
                                   listenerVel.z * toSourceNorm.z;

    // Calculate doppler shift using the standard formula
    // f_observed = f_emitted * (c + v_listener) / (c + v_source)
    Float32 relativeVelocity = listenerRadialSpeed - sourceRadialSpeed;
    Float32 dopplerShift = (m_speedOfSound + relativeVelocity) / m_speedOfSound;

    // Clamp to reasonable values to avoid extreme pitch shifts
    dopplerShift = std::max(0.5f, std::min(2.0f, dopplerShift));

    // Apply global and per-source doppler factors
    Float32 targetPitch = 1.0f + (dopplerShift - 1.0f) * m_dopplerFactor * 
                                  source->GetDopplerFactor();

    // Smooth pitch transitions to avoid jarring changes
    Float32 smoothingFactor = std::min(1.0f, deltaTime * 10.0f);
    state.smoothedPitch = state.smoothedPitch * (1.0f - smoothingFactor) + 
                          targetPitch * smoothingFactor;

    source->SetPitch(state.smoothedPitch);

    // Store state for next frame
    state.lastPosition = sourcePos;
    state.lastDistance = distance;
}
```

#### Key Features
- **Automatic Velocity Calculation**: If velocity is not set, it's derived from position delta
- **Radial Velocity**: Only velocity along listener-source line affects Doppler
- **Clamping**: Pitch shift limited to [0.5, 2.0] to prevent extreme distortion
- **Smoothing**: Pitch changes are interpolated to avoid jarring transitions
- **Per-Source Factor**: Each source can have individual Doppler sensitivity

#### Configuration

```cpp
// Global Doppler settings
audioManager->SetSpeedOfSound(343.3f);  // m/s (default)
audioManager->SetDopplerFactor(1.0f);   // Global multiplier

// Per-source Doppler
source->SetDopplerFactor(0.5f);  // Reduce Doppler effect
source->SetDopplerFactor(0.0f);  // Disable Doppler for this source
```

### Distance Attenuation

Distance attenuation reduces volume as the listener moves away from a source.

```cpp
// Configure attenuation
source->SetAttenuationModel(EAttenuationModel::Inverse);
source->SetMinDistance(10.0f);   // Full volume within 10 units
source->SetMaxDistance(100.0f);  // Silent beyond 100 units
source->SetRolloffFactor(1.0f);  // Standard falloff rate
```

### Spatialization

Sources can be 2D (screen-space) or 3D (world-space):

```cpp
// 2D sound (UI, music)
source->SetSpatial(false);

// 3D sound (footsteps, explosions)
source->SetSpatial(true);
source->SetPosition(FVector3(10.0f, 0.0f, 5.0f));
```

## Best Practices

### Performance

1. **Reuse Buffers**: Always use `LoadBuffer()` through the manager to leverage caching
   ```cpp
   // Good
   auto buffer = audioManager->LoadBuffer("sound.wav");
   
   // Bad (bypasses cache)
   auto buffer = audioManager->CreateBuffer();
   buffer->LoadFromFile("sound.wav");
   ```

2. **Use Streams for Large Files**: Music and long ambient sounds should use `IAudioStream`
   ```cpp
   // Good for 10MB music file
   auto stream = audioManager->CreateStream();
   stream->OpenFromFile("music.ogg");
   
   // Bad (loads 10MB into RAM)
   auto buffer = audioManager->LoadBuffer("music.ogg");
   ```

3. **Limit Active Sources**: Keep the number of simultaneously playing sources reasonable (<32)
   ```cpp
   // Automatic cleanup of stopped sources happens in Update()
   audioManager->Update(deltaTime);
   ```

4. **Unload Unused Buffers**: Free memory when audio is no longer needed
   ```cpp
   audioManager->UnloadBuffer("Assets/Audio/level1_music.ogg");
   audioManager->UnloadAllBuffers();  // For level transitions
   ```

### 3D Audio

1. **Update Listener Every Frame**: Keep listener synchronized with camera
   ```cpp
   void Tick(Float32 deltaTime) override
   {
       IAudioListener* listener = audioManager->GetListener();
       listener->SetPosition(camera->GetPosition());
       listener->SetOrientation(camera->GetForwardVector(), camera->GetUpVector());
   }
   ```

2. **Set Appropriate Attenuation**: Match attenuation to sound type
   ```cpp
   // Loud explosion (heard from far away)
   source->SetMinDistance(20.0f);
   source->SetMaxDistance(500.0f);
   
   // Quiet footsteps (heard only nearby)
   source->SetMinDistance(2.0f);
   source->SetMaxDistance(30.0f);
   ```

3. **Use Doppler Sparingly**: Disable Doppler for non-moving sources
   ```cpp
   source->SetDopplerFactor(0.0f);  // Static ambient sound
   ```

4. **Position Updates**: Update source positions for moving actors
   ```cpp
   void Tick(Float32 deltaTime) override
   {
       m_audioSource->SetPosition(GetPosition());
       m_audioSource->SetVelocity(GetVelocity());
   }
   ```

### Memory Management

1. **Use Smart Pointers**: Audio objects are managed with `TSharedPtr`
   ```cpp
   TSharedPtr<IAudioBuffer> buffer = audioManager->LoadBuffer("sound.wav");
   // Automatic cleanup when reference count reaches zero
   ```

2. **Asset Integration**: Load from assets for embedded data
   ```cpp
   const UAsset* asset = assetManager->GetAsset("sound.wav");
   auto buffer = audioManager->LoadBuffer(asset);
   ```

3. **Thread Safety**: Audio manager operations are thread-safe
   ```cpp
   // Safe to call from any thread
   audioManager->PlaySound("click.wav");
   ```

### Error Handling

1. **Check Load Results**: Validate buffer/stream loading
   ```cpp
   auto buffer = audioManager->LoadBuffer("sound.wav");
   if (!buffer)
   {
       LOG_ERROR("Failed to load sound: sound.wav");
       return;
   }
   ```

2. **Validate Assets**: Check asset existence before loading
   ```cpp
   const UAsset* asset = assetManager->GetAsset("sound.wav");
   if (!asset || asset->GetData().empty())
   {
       LOG_ERROR("Invalid audio asset");
       return;
   }
   ```

### Audio Design

1. **Volume Hierarchy**: Use consistent volume ranges
   ```cpp
   // UI sounds: 0.5 - 0.8
   audioManager->PlaySound("button.wav", 0.6f);
   
   // Music: 0.3 - 0.6
   musicStream->SetVolume(0.5f);
   
   // SFX: 0.7 - 1.0
   audioManager->PlaySound("explosion.wav", 1.0f);
   ```

2. **Loop Seamlessly**: Use loop points for continuous sounds
   ```cpp
   source->SetLooping(true);  // Ensure audio file has seamless loop
   ```

3. **Prioritize Audio**: Stop less important sounds when source limit is reached
   ```cpp
   // Example: Stop oldest footstep when playing new one
   if (activeFootstepSources.size() >= MAX_FOOTSTEPS)
   {
       activeFootstepSources[0]->Stop();
       activeFootstepSources.erase(activeFootstepSources.begin());
   }
   ```

## Conclusion

The Audio module provides a robust, flexible system for 2D and 3D audio in the TKD Engine. The interface-based architecture ensures future extensibility, while the SFML implementation offers solid, cross-platform audio playback with spatial audio capabilities.

Key strengths:
- **Clean abstraction**: Interface layer enables backend replacement
- **Feature-rich**: 3D audio, streaming, Doppler, multiple attenuation models
- **Performance-conscious**: Buffer caching, automatic source cleanup, streaming for large files
- **Thread-safe**: Mutex-protected operations
- **Asset integration**: Direct loading from engine asset system
- **Easy to use**: Convenience methods for common use cases

Current limitations (SFML-specific):
- Limited audio effect support (placeholder only)
- No directional/cone audio
- No custom DSP processing
- Device selection not fully supported

For most game audio needs (2D/3D sound effects, music, ambient audio), the Audio module provides comprehensive functionality with minimal overhead.
