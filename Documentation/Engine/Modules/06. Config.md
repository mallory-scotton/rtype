# Config Module Documentation
---

## Overview

The Config module serves as the foundation of the TKD Engine, providing:
- **Platform Detection**: Automatic identification of operating system and architecture
- **Version Management**: Centralized version information and build metadata
- **Type Definitions**: Consistent primitive types and standard library aliases
- **Configuration Macros**: Build-time configuration and utility macros
- **Engine Settings**: Comprehensive runtime configuration structure
- **Input Definitions**: Unified input system enumerations

This module is designed to be included first in all engine code, establishing the baseline types, macros, and configuration that the rest of the engine depends on.

### Key Features

- **Cross-Platform**: Supports Windows, Linux, macOS, iOS, Android, and BSD variants
- **Architecture Detection**: Identifies x86, x86_64, ARM, and ARM64 architectures
- **Build Configuration**: Distinguishes between client/server, debug/release, static/dynamic
- **Type Safety**: Strongly-typed primitives with explicit bit widths
- **Standard Library Integration**: Convenient aliases for std types
- **Compile-Time Configuration**: Preprocessor-based feature detection
- **Runtime Settings**: Flexible configuration structure for all engine subsystems

## Architecture

### Module Structure

```
Engine/Source/Engine/Config/
├── Config.hpp            # Main configuration header (platform, build type)
├── Types.hpp             # Primitive types and std aliases
├── Macros.hpp            # Utility macros (SafeDelete, bitwise enums)
├── Constants.hpp         # Compile-time constants
├── Enumerations.hpp      # Engine-level enumerations
├── EInputs.hpp           # Input system enumerations
└── FEngineSettings.hpp   # Runtime configuration structure
```

### Inclusion Hierarchy

```cpp
#include <Engine/Config.hpp>  // Top-level header includes:
  ├─ Config/Config.hpp       // Platform, version, build type
  ├─ Config/Types.hpp        // Type definitions
  ├─ Config/Macros.hpp       // Utility macros
  ├─ Config/Constants.hpp    // Compile-time constants
  ├─ Config/EInputs.hpp      // Input enumerations
  └─ Config/FEngineSettings.hpp  // Runtime settings
```

```cpp
namespace tkd
{

    typedef signed short Int16;        // [-32,768; 32,767]
    typedef signed int Int32;          // [-2,147,483,648; 2,147,483,647]
    typedef signed long long Int64;    // [-9,223,372,036,854,775,808; ...]
    
    // Unsigned integers
    typedef unsigned char UInt8;       // [0; 255]
    typedef unsigned short UInt16;     // [0; 65,535]
    typedef unsigned int UInt32;       // [0; 4,294,967,295]
    typedef unsigned long long UInt64; // [0; 18,446,744,073,709,551,615]

    typedef double Float64;            // IEEE 754 double precision
    
    // Boolean and byte
    typedef bool Bool;                 // true or false
    typedef unsigned char Byte;        // 8 bits
    
    // Size type
    using SizeT = decltype(sizeof(0));
}
```

### Utility Macros

#### Memory Management

```cpp
#define SafeDelete(x) if (x) { delete x; x = nullptr; }
#define SafeDeleteArray(x) if (x) { delete[] x; x = nullptr; }
```

Usage:
```cpp
MyClass* obj = new MyClass();
SafeDelete(obj);  // Deletes and nullifies

int* array = new int[100];
SafeDeleteArray(array);  // Deletes array and nullifies
```

#### Class Member Control

```cpp
// Disable copy constructor and copy assignment
#define TKD_DISABLE_COPY(Class)          \
    Class(const Class&) = delete;       \
    Class& operator=(const Class&) = delete;

// Disable move constructor and move assignment
#define TKD_DISABLE_MOVE(Class)          \
    Class(Class&&) = delete;            \
    Class& operator=(Class&&) = delete;

// Disable both copy and move
#define TKD_DISABLE_COPY_MOVE(Class)     \
    TKD_DISABLE_COPY(Class)             \
    TKD_DISABLE_MOVE(Class)
```

Usage:
```cpp
class Singleton
{
public:
    static Singleton& GetInstance();
    
    TKD_DISABLE_COPY_MOVE(Singleton)
    
private:
    Singleton() = default;
};
```

#### Attribute Macros

```cpp
// Unused variable (suppress warnings)
#define TKD_UNUSED(x) (void)(x)

// Maybe unused attribute
#if defined(__GNUC__) || defined(__clang__)
    #define TKD_MAYBE_UNUSED __attribute__((unused))
#else
    #define TKD_MAYBE_UNUSED
#endif

// No discard (warn if return value ignored)
#if defined(__GNUC__) || defined(__clang__)
    #define TKD_NODISCARD [[nodiscard]]
#else
    #define TKD_NODISCARD
#endif

// Weak linking support
#if defined(__GNUC__) || defined(__clang__)

#elif defined(_MSC_VER)
    #define TKD_WEAK __declspec(selectany)
#else
    #define TKD_WEAK
#endif

// Force inline
#if defined(TKD_FORCE_INLINE)
    #define FORCEINLINE inline
#else
    #define FORCEINLINE
#endif
```

Usage:

#### Enum Bitwise Operations

```cpp
#define ENABLE_BITWISE_ENUM_OPERATORS(EnumName) \
constexpr EnumName operator|(EnumName lhs, EnumName rhs) { /* ... */ } \
constexpr EnumName operator&(EnumName lhs, EnumName rhs) { /* ... */ } \
constexpr EnumName operator~(EnumName flag) { /* ... */ }
```

Usage:
```cpp
enum class EFileMode : UInt32
{
    Read   = 1 << 0,
    Write  = 1 << 1,
    Append = 1 << 2,
    Binary = 1 << 3
};

ENABLE_BITWISE_ENUM_OPERATORS(EFileMode)

// Combine flags

// Check flag
if ((mode & EFileMode::Read) == EFileMode::Read)
{
    // Read mode is set
}
```

```cpp
class ResourceManager
{
private:
    std::unordered_map<std::string, TSharedPtr<Texture>> m_textures;
    
public:
    TSharedPtr<Texture> LoadTexture(const std::string& path)
    {
        auto it = m_textures.find(path);
        if (it != m_textures.end())
        {
            return it->second;  // Return cached texture
        }
        
        auto texture = std::make_shared<Texture>();
        if (texture->LoadFromFile(path))
        {
            m_textures[path] = texture;
            return texture;
        }
        
        return nullptr;
    }
};
```

## Best Practices

### Type Safety

1. **Always use engine types**: Prefer `UInt32` over `unsigned int` for consistency
   ```cpp
   // Good
   UInt32 entityId = 12345;
   Float32 deltaTime = 0.016f;
   
   // Avoid
   unsigned int entityId = 12345;
   float deltaTime = 0.016f;
   ```

2. **Use fixed-width types for serialization**: Ensures consistent data size across platforms
   ```cpp
   struct NetworkPacket
   {
       UInt32 packetId;    // Always 4 bytes
       UInt16 dataSize;    // Always 2 bytes
       Float32 timestamp;  // Always 4 bytes
   };
   ```

3. **Prefer smart pointers**: Use `TSharedPtr` and `TUniquePtr` over raw pointers
   ```cpp
   // Good
   TSharedPtr<Actor> actor = std::make_shared<Actor>();
   
   // Avoid
   Actor* actor = new Actor();
   ```

### Platform Handling

1. **Use platform macros for platform-specific code**:
   ```cpp
   #ifdef TKD_SYSTEM_WINDOWS
       #include <windows.h>
   #elif defined(TKD_SYSTEM_LINUX)
       #include <unistd.h>
   #endif
   ```

2. **Test on all target platforms**: Don't assume behavior is consistent
   
3. **Use portable types**: Avoid platform-specific types like `DWORD`, `long`, etc.

### Configuration Management

1. **Initialize FEngineSettings early**: Before any subsystem initialization
   ```cpp
   int main()
   {
       FEngineSettings settings;
       LoadSettings(settings);  // Load from file/command line
       
       InitializeEngine(settings);
       // ...
   }
   ```

2. **Validate settings**: Ensure values are within acceptable ranges
   ```cpp
   void ValidateSettings(FEngineSettings& settings)
   {
       settings.window.targetFPS = std::clamp(settings.window.targetFPS, 30, 300);
       settings.audio.masterVolume = std::clamp(settings.audio.masterVolume, 0, 100);
   }
   ```

3. **Provide sensible defaults**: FEngineSettings has default values for all fields

### Macro Usage

1. **Prefer inline functions over macros when possible**:
   ```cpp
   // Good (type-safe)
   template<typename T>
   inline void SafeDelete(T*& ptr)
   {
       if (ptr) { delete ptr; ptr = nullptr; }
   }
   
   // Acceptable for backward compatibility
   #define SafeDelete(x) if (x) { delete x; x = nullptr; }
   ```

2. **Use uppercase for macro names**: Distinguish macros from functions
   ```cpp
   #define TKD_VERSION_MAJOR 1  // Good
   #define tkd_version_major 1  // Avoid
   ```

3. **Document macro side effects**: Explain what macros do
   ```cpp
   /// \brief Disables copy constructor and assignment operator
   #define TKD_DISABLE_COPY(Class) /* ... */
   ```

### Debug and Release

1. **Use TKD_DEBUG for debug-only code**:
   ```cpp
   #ifdef TKD_DEBUG
       void ValidateState() { /* expensive validation */ }
   #else
       void ValidateState() { /* no-op in release */ }
   #endif
   ```

2. **Keep debug code minimal**: Avoid performance-heavy debug checks in hot paths

3. **Use assertions**: Assert assumptions during development
   ```cpp
   #ifdef TKD_DEBUG
       #define TKD_ASSERT(condition) assert(condition)
   #else
       #define TKD_ASSERT(condition) ((void)0)
   #endif
   ```

### Client/Server Separation

1. **Use build type macros for exclusive code**:
   ```cpp
   TKD_ENGINE_IF_CLIENT(
       InitializeRenderer();
   )
   
   TKD_ENGINE_IF_SERVER(
       InitializeHeadlessMode();
   )
   ```

2. **Share common code**: Put shared logic in base classes or separate modules

3. **Test both builds**: Ensure client and server builds compile and run correctly

## Conclusion

The Config module is the foundational layer of the TKD Engine, providing:

**Key Strengths:**
- **Cross-platform support**: Automatic detection of OS and architecture
- **Type safety**: Consistent fixed-width types across platforms
- **Flexibility**: Comprehensive runtime configuration structure
- **Convenience**: Standard library aliases and utility macros
- **Compile-time configuration**: Build-type and platform-specific code
- **Input system foundation**: Complete input enumeration definitions

**Design Philosophy:**
- **Consistent naming**: All types, macros, and constants follow TKD conventions
- **Explicit types**: Fixed-width integers eliminate platform ambiguity
- **Smart defaults**: FEngineSettings provides sensible default values
- **Extensibility**: Easy to add new configuration categories
- **Documentation**: Well-documented macros and types

The Config module should be the first include in all engine code, establishing the baseline types and configuration that the entire engine depends on. Its comprehensive nature ensures consistent behavior across platforms while providing the flexibility needed for diverse game requirements.
