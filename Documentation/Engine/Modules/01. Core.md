# 🧱 Core

## Overview

The **Core** module is the foundation layer of the TKD Engine, providing essential functionality that all other modules depend on. It offers a comprehensive suite of tools including mathematical primitives, data structures, memory management, object reflection system, concurrency utilities, logging, serialization, and more.

Core is designed to be:
- **Zero-dependency**: Relies only on standard C++ library
- **Template-heavy**: Extensive use of templates for type safety and performance
- **Platform-agnostic**: Works across different platforms and compilers
- **Thread-safe**: Core components provide thread-safe operations where needed

## Architecture

The Core module is organized into **7 major subsystems**:

```
Core/
├── Math/            - Mathematical primitives and operations
├── Containers/      - Custom data structures and string handling
├── Memory/          - Memory management and smart pointers
├── Object/          - Reflection system and base object classes
├── Concurrency/     - Threading and synchronization primitives
├── Utils/           - Utilities (logging, filesystem, events, UUID)
└── Archives/        - Serialization and deserialization system
```

Each subsystem provides header files that can be included independently, with top-level headers (`Math.hpp`, `Containers.hpp`, etc.) for convenience.

### Quaternions

```cpp
    void FromEulerAngles(T pitch, T yaw, T roll);

using FQuaternion = TQuaternion<Float32>;
```

**Usage:**

```cpp
// Create rotation from axis-angle
FVector3 axis = FVector3::Up;
FQuaternion rot(axis, 45.0f);  // 45 degrees around Y-axis

// Create from Euler angles
FQuaternion euler(30.0f, 45.0f, 60.0f);  // Pitch, Yaw, Roll

// Rotate a vector
FVector3 direction = FVector3::Forward;
FVector3 rotated = rot.RotateVector(direction);

// Combine rotations
FQuaternion combined = rot1 * rot2;

// Smooth interpolation
FQuaternion interpolated = FQuaternion::Slerp(q1, q2, 0.5f);

// Convert to matrix for GPU
FMatrix4x4 matrix = rot.ToMatrix();
```

**Usage:**

```cpp
// Register a class
UClass* myClass = UClass::RegisterClass("MyGameObject", parentClass);

myClass->AddProperty("Position", EDefinitionSource::Native);

// Create instance via reflection
UClass* foundClass = UClass::FindClass("MyGameObject");
if (foundClass) {
    UObject* instance = foundClass->CreateInstance();

// Check inheritance
UClass* baseClass = UClass::FindClass("UObject");

}

// Get all derived classes
std::vector<UClass*> derived = UClass::GetDerivedClasses(baseClass);
```

```cpp
enum class EArchiveMode : UInt8
{
    None,
    Loading,  // Reading/deserialization

class FArchive
{
protected:
    std::vector<UInt8> m_data;  // Binary data buffer
    Int32 m_version;            // Archive version
    EArchiveMode m_mode;        // Current mode
    bool m_allowSeek;           // Seeking enabled?
    SizeT m_position;           // Current position
    
public:

        return *this;
    }
    
    // Raw data serialization
    void Serialize(void* data, SizeT size);
    
    template <typename T>
    typename std::enable_if_t<std::is_trivially_copyable_v<T>, void>
    Serialize(T* value, SizeT length = 1);
    
    // Stream operations
    SizeT Tell() const;
    void Seek(SizeT position);
    SizeT TotalSize() const;
    
    // Version management
    Int32 GetVersion() const;
    void SetVersion(Int32 version);
    
    // Mode and data access
    EArchiveMode GetMode() const;
    const std::vector<UInt8>& GetData() const;
    void SetData(const std::vector<UInt8>& data);
```

## Design Patterns

### Reflection Pattern

The Core module implements a **reflection system** similar to Unreal Engine:

1. **UObject** provides base functionality
2. **UClass** stores metadata
3. **DECLARE_CLASS** macro registers classes
4. Properties and functions are registered at construction
5. Runtime type information enables serialization, networking, scripting

### Template-Based Math

Mathematical types use **templates** for:
- Type flexibility (float, double, int)
- Zero-cost abstractions
- Compile-time optimizations
- Type safety

### Singleton Pattern

**TSingleton** provides:
- Thread-safe lazy initialization
- Optional constructor arguments
- Instance lifetime management
- Global access point

## Performance Considerations

### 1. Template Instantiation

Templates are instantiated at compile time. Common types (Float32, Float64) are likely pre-instantiated, but exotic types may increase compile time and binary size.

### 2. Stack vs Heap Allocation

```cpp
// Stack allocation (fast)
FVector3 position(10.0f, 20.0f, 30.0f);
TArray<int, 100> fixedArray;

// Heap allocation (slower, but flexible size)
TVector<int> dynamicArray;
UObject* obj = new UObject();
```

### 3. Avoid Unnecessary Copies

```cpp
// Pass by const reference
void ProcessVector(const FVector3& v);

// Use move semantics
FString CreateLargeString();
FString result = CreateLargeString();  // Move, not copy
```

### 4. Reserve Capacity

```cpp
TVector<FVector3> points;
points.Reserve(1000);  // Avoid multiple reallocations
for (int i = 0; i < 1000; ++i) {
    points.PushBack(GeneratePoint(i));
}
```

### 5. Reflection Overhead

Reflection has runtime cost. Use direct member access when reflection isn't needed:

```cpp
// Direct access (fast)
player->m_health = 100.0f;

// Reflection (slower, but flexible)
player->GetProperty("Health")->SetValue(&player, 100.0f);
```

## Thread Safety

### Thread-Safe Components

- **FLogger**: Fully thread-safe with internal mutex
- **TSingleton**: Thread-safe lazy initialization via `std::once_flag`
- **UObject registry**: Protected by `s_objectMutex`

### Not Thread-Safe

- Individual **UObject** instances (require external synchronization)
- **Containers** (TArray, TVector, FString) - not thread-safe by design
- **Math types** (vectors, matrices) - value types, thread-safe if not shared

### Best Practices

```cpp
// Protect shared resources
std::mutex resourceMutex;
UObject* sharedObject;

void ThreadFunction()
{
    std::lock_guard lock(resourceMutex);
    sharedObject->SetProperty("Value", 42);
}
```
