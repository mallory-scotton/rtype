# 🗂️ Directory Layout

## Overview

This document provides a comprehensive guide to the R-Type project directory structure. Understanding this layout is essential for navigating the codebase, locating specific functionality, and contributing to the project.

The project follows a modular architecture with clear separation between the engine, game implementations, tools, and documentation. Each major component is organized into logical subdirectories with consistent naming conventions.

### Key Root Files

- **`CMakeLists.txt`**: Root CMake build configuration that includes all subprojects

#### Documentation Files
- **`README.md`**: Primary project documentation with quick start guide

### Tool Descriptions

#### TKDPack
Asset packaging utility for creating `.pak` archives:
- **Purpose**: Bundle multiple assets into single package files
- **Input**: Individual `.uasset` files or directories
- **Output**: `.pak` package files
- **Features**: Compression, indexing, fast lookup

#### TKDEmbed
Resource embedding utility for compile-time asset inclusion:
- **Purpose**: Embed resources directly into executables
- **Input**: Any binary file (images, configs, etc.)
- **Output**: C++ header files with byte arrays
- **Features**: Namespace generation, size constants

#### TKDGraph
Graph visualization and debugging tool:
- **Purpose**: Visualize engine systems and relationships
- **Features**: Network graphs, performance profiling, entity hierarchies

## Navigation Guidelines

### Finding Functionality

To locate specific functionality:

1. **Core Systems** (math, containers, utilities): `Engine/Source/Engine/Core/`
2. **Game Runtime** (actors, components, world): `Engine/Source/Engine/Runtime/`
3. **Networking**: `Engine/Source/Engine/Network/`
4. **Graphics**: `Engine/Source/Engine/Renderer/`
5. **Audio**: `Engine/Source/Engine/Audio/`
6. **Asset Management**: `Engine/Source/Engine/Assets/`
7. **Game Logic**: `Games/RType/Source/` or `Games/BeatSaber/Source/`
8. **Tools**: `Tools/TKDPack/`, `Tools/TKDEmbed/`, `Tools/TKDGraph/`
9. **Documentation**: `Documentation/`
10. **Build Scripts**: `Scripts/`

### Module Headers

Each module provides an aggregator header that includes all subcomponents:

- **`Engine/Source/Engine/Core.hpp`**: Includes all Core functionality
- **`Engine/Source/Engine/Runtime.hpp`**: Includes all Runtime components
- **`Engine/Source/Engine/Network.hpp`**: Includes all Network classes
- **`Engine/Source/Engine/Renderer.hpp`**: Includes all Renderer interfaces
- **`Engine/Source/Engine/Audio.hpp`**: Includes all Audio systems
- **`Engine/Source/Engine.hpp`**: Includes the entire engine

### Header Organization

Headers follow a consistent pattern:

```cpp
// Module headers (public API)
#include <Engine/Core.hpp>
#include <Engine/Runtime.hpp>
```

## Best Practices

### Adding New Files

When adding new files to the project:

1. **Choose the correct directory** based on functionality
2. **Follow naming conventions**:
   - Classes: PascalCase with prefix (AActor, UComponent, FStruct, IInterface, EEnum, T Template)
   - Files: Match class name (AActor.hpp, AActor.cpp)
3. **Update CMakeLists.txt** in the relevant directory
4. **Add to module header** if it's part of public API
5. **Follow include guard pattern**: `#pragma once`
6. **Document with Doxygen comments**

### Module Independence

Modules are designed to be relatively independent:

- **Core**: No dependencies on other modules
- **Runtime**: Depends on Core
- **Network**: Depends on Core
- **Renderer**: Depends on Core
- **Audio**: Depends on Core and Assets
- **Assets**: Depends on Core
- **Static**: Depends on all modules (facade pattern)

### Build Configuration

Build configurations are located in:

- **Global**: `CMakeLists.txt` (root)
- **Engine**: `Engine/CMakeLists.txt`
- **Games**: `Games/*/CMakeLists.txt`
- **Tools**: `Tools/*/CMakeLists.txt`
- **Dependencies**: `conanfile.py`

## Summary

The R-Type project follows a clear, modular directory structure:

- **`Engine/`**: Complete game engine implementation with modular architecture
- **`Games/`**: Game projects built on the engine (R-Type, Beat Saber)
- **`Tools/`**: Development utilities (TKDPack, TKDEmbed, TKDGraph)
- **`Documentation/`**: Comprehensive documentation for all components
- **`Build/`**: Generated build artifacts (not in version control)
- **`Scripts/`**: Automated build and utility scripts
- **`Tests/`**: Engine tests and example applications

This organization promotes:

✅ **Modularity**: Clear separation of concerns  
✅ **Reusability**: Engine can be used for multiple games  
✅ **Maintainability**: Easy to navigate and understand  
✅ **Scalability**: Simple to add new modules and features  
✅ **Documentation**: Well-documented structure and APIs  

For questions about specific directories or files, refer to the relevant README.md files or consult the detailed documentation in `Documentation/Engine/`.
